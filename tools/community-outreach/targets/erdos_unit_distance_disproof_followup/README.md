# Stage-1 verification artifact for arXiv:2605.20695

This directory contains an independent Stage-1 computational verification artifact for the line of work around the recent disproof of Erdős's unit-distance conjecture.

Paper:

> Alon, Bloom, Gowers, Litt, Sawin, Shankar, Tsimerman, Wang, Wood. Remarks on the disproof of the unit distance conjecture. arXiv:2605.20695, May 2026.

The paper itself ships no code. This artifact fills part of that reproducibility gap by checking the explicit algebraic-data consequences that can be verified with small, transparent, standard-library-only computation.

## Stage-1 scope

The checker `check_2605_20695_LT_construction_stage1.py` verifies the explicit example

```text
T = {3, 5, 7, 11, 13, 17}
S = {101, infinity}
L_T = Q(sqrt(5), sqrt(13), sqrt(17), sqrt(21), sqrt(33))
```

It checks:

- The multiquadratic degree computation for `L_T`. The degree is `2^k`, where `k` is the rank over `F_2` of the subgroup of `Q*/(Q*)^2` generated by `{5, 13, 17, 21, 33}`. The squarefree exponent vectors over primes `{3, 5, 7, 11, 13, 17}` have rank `5`, so `[L_T:Q] = 32`.
- The claim that `101` splits completely in `L_T`. For odd `p` not dividing the generators, `p` splits completely in a multiquadratic field iff each generator is a quadratic residue modulo `p`. The checker computes the Legendre symbols `(5/101)`, `(13/101)`, `(17/101)`, `(21/101)`, and `(33/101)` by Euler's criterion.
- A cross-check of the prime-generator directions `(101/q)` for `q in {3, 5, 7, 11, 13, 17}` via direct Euler-criterion Legendre-symbol evaluation.
- The paper's stated rank inequalities `d(G_T^S) = 5` and `r(G_T^S) <= 6` only at the consequence level: given those claimed bounds, the Golod-Shafarevich inequality is `d^2 > 4r`, namely `25 > 24`, so the pro-p tower criterion passes.

The checker is intentionally honest about the boundary of this Stage-1 artifact. Computing `d(G_T^S)` and `r(G_T^S)` from scratch requires class field theory and S-unit infrastructure, not just Python's standard library. The JSON output therefore marks that part as `INSUFFICIENT_INFRASTRUCTURE` and records that PARI/GP-style `bnfinit`/`bnrclassfield` computations or Sage's `K.S_class_group`-level machinery would be needed for a future deeper stage.

## Future stages

Future verification stages should tackle the parts outside this standard-library Stage-1 check:

- tower construction;
- norm-1 element production and certification;
- complex embedding choices and numerical stability;
- n-point unit-distance counting for the resulting configurations.
