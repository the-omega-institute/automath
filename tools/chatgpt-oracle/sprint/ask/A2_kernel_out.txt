# Brainstorming Ideas Into Designs

Help turn ideas into fully formed designs and specs through natural collaborative dialogue.

Start by understanding the current project context, then ask questions one at a time to refine the idea. Once you understand what you're building, present the design and get user approval.

<HARD-GATE>
Do NOT invoke any implementation skill, write any code, scaffold any project, or take any implementation action until you have presented a design and the user has approved it. This applies to EVERY project regardless of perceived simplicity.
</HARD-GATE>

## Anti-Pattern: "This Is Too Simple To Need A Design"

Every project goes through this process. A todo list, a single-function utility, a config change â€” all of them. "Simple" projects are where unexamined assumptions cause the most wasted work. The design can be short (a few sentences for truly simple projects), but you MUST present it and get approval.

## Checklist

You MUST create a task for each of these items and complete them in order:

1. **Explore project context** â€” check files, docs, recent commits
2. **Offer visual companion** (if topic will involve visual questions) â€” this is its own message, not combined with a clarifying question. See the Visual Companion section below.
3. **Ask clarifying questions** â€” one at a time, understand purpose/constraints/success criteria
4. **Propose 2-3 approaches** â€” with trade-offs and your recommendation
5. **Present design** â€” in sections scaled to their complexity, get user approval after each section
6. **Write design doc** â€” save to `docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md` and commit
7. **Spec self-review** â€” quick inline check for placeholders, contradictions, ambiguity, scope (see below)
8. **User reviews written spec** â€” ask user to review the spec file before proceeding

## The Process

**Understanding the idea:**

- Check out the current project state first (files, docs, recent commits)
- Before asking detailed questions, assess scope: if the request describes multiple independent subsystems (e.g., "build a platform with chat, file storage, billing, and analytics"), flag this immediately. Don't spend questions refining details of a project that needs to be decomposed first.
- If the project is too large for a single spec, help the user decompose into sub-projects: what are the independent pieces, how do they relate, what order should they be built? Then brainstorm the first sub-project through the normal design flow. Each sub-project gets its own spec â†’ plan â†’ implementation cycle.
- For appropriately-scoped projects, ask questions one at a time to refine the idea
- Prefer multiple choice questions when possible, but open-ended is fine too
- Only one question per message - if a topic needs more exploration, break it into multiple questions
- Focus on understanding: purpose, constraints, success criteria

**Exploring approaches:**

- Propose 2-3 different approaches with trade-offs
- Present options conversationally with your recommendation and reasoning
- Lead with your recommended option and explain why

**Presenting the design:**

- Once you believe you understand what you're building, present the design
- Scale each section to its complexity: a few sentences if straightforward, up to 200-300 words if nuanced
- Ask after each section whether it looks right so far
- Cover: architecture, components, data flow, error handling, testing
- Be ready to go back and clarify if something doesn't make sense

**Design for isolation and clarity:**

- Break the system into smaller units that each have one clear purpose, communicate through well-defined interfaces, and can be understood and tested independently
- For each unit, you should be able to answer: what does it do, how do you use it, and what does it depend on?
- Can someone understand what a unit does without reading its internals? Can you change the internals without breaking consumers? If not, the boundaries need work.
- Smaller, well-bounded units are also easier for you to work with - you reason better about code you can hold in context at once, and your edits are more reliable when files are focused. When a file grows large, that's often a signal that it's doing too much.

**Working in existing codebases:**

- Explore the current structure before proposing changes. Follow existing patterns.
- Where existing code has problems that affect the work (e.g., a file that's grown too large, unclear boundaries, tangled responsibilities), include targeted improvements as part of the design - the way a good developer improves code they're working in.
- Don't propose unrelated refactoring. Stay focused on what serves the current goal.

## After the Design

**Documentation:**

- Write the validated design (spec) to `docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md`
  - (User preferences for spec location override this default)
- Use elements-of-style:writing-clearly-and-concisely skill if available
- Commit the design document to git

**Spec Self-Review:**
After writing the spec document, look at it with fresh eyes:

1. **Placeholder scan:** Any "TBD", "TODO", incomplete sections, or vague requirements? Fix them.
2. **Internal consistency:** Do any sections contradict each other? Does the architecture match the feature descriptions?
3. **Scope check:** Is this focused enough for a single implementation plan, or does it need decomposition?
4. **Ambiguity check:** Could any requirement be interpreted two different ways? If so, pick one and make it explicit.

Fix any issues inline. No need to re-review â€” just fix and move on.

**User Review Gate:**
After the spec review loop passes, ask the user to review the written spec before proceeding:

> "Spec written and committed to `<path>`. Please review it and let me know if you want to make any changes before we start writing out the implementation plan."

Wait for the user's response. If they request changes, make them and re-run the spec review loop. Only proceed once the user approves.

**Implementation:**

- Invoke the writing-plans skill to create a detailed implementation plan
- Do NOT invoke any other skill. writing-plans is the next step.

## Key Principles

- **One question at a time** - Don't overwhelm with multiple questions
- **Multiple choice preferred** - Easier to answer than open-ended when possible
- **YAGNI ruthlessly** - Remove unnecessary features from all designs
- **Explore alternatives** - Always propose 2-3 approaches before settling
- **Incremental validation** - Present design, get approval before moving on
- **Be flexible** - Go back and clarify when something doesn't make sense

\subsection*{The positive tail-jet mechanism for an abstract kernel}

We now separate the kernel properties from their stable implementation.  Fix
an integer \(r\ge1\).  A strictly positive probability density
\(p\in C^r(\RR^d)\) will be called \emph{tail-jet admissible of order \(r\)}
if the following three conditions hold.
\begin{enumerate}[label=\textup{(K\arabic*)},leftmargin=2.8em]
\item For every multi-index \(\gamma\) with \(1\le|\gamma|\le r\),
\[
 \left\|\frac{\partial^\gamma p}{p}\right\|_\infty<\infty.
\]
\item The top normalized derivative has the quotient translation modulus
\[
 \omega_{p,r}(t):=
 \max_{|\gamma|=r}\ \sup_{|h|\le t}
 \left\|\frac{\partial^\gamma p(\mathord\cdot-h)
                   -\partial^\gamma p}{p}\right\|_\infty,
 \qquad 0<t\le1,
\]
finite for \(0<t\le1\) and satisfying
\(\omega_{p,r}(t)\to0\) as \(t\downarrow0\).
\item The translate entropy is finite and, for some \(C_{p,r}<\infty\),
\[
 \mathsf H_p(z):=
 D_{\rm KL}\bigl(p(\mathord\cdot-z)\|p\bigr)
 \le C_{p,r}(1+|z|^r),\qquad z\in\RR^d.
\]
\end{enumerate}
Put \(p_s(x)=s^{-d}p(x/s)\),
\(\Omega_p(\dd y)=p(y)\dd y\), and
\[
 F_y^p(z)=\frac{p(y-z)}{p(y)}.
\]
For a law \(\lambda\) with finite \(r\)th absolute moment define
\[
 B_{p,j}^\lambda(y):=
 \frac{(-1)^j}{p(y)}
 \sum_{|\gamma|=j}\frac{m_\gamma(\lambda)}{\gamma!}
 \partial^\gamma p(y),\qquad 1\le j\le r.
\]

\begin{unnumberedtheorem}[Abstract positive tail-jet kernel theorem]
Let \(p\) be tail-jet admissible of order \(r\), and let \(\nu,\eta\) be
probability laws on \(\RR^d\) such that
\[
 m_\gamma(\nu)=m_\gamma(\eta)\quad(|\gamma|<r),
 \qquad \int |x|^r(\nu+\eta)(\dd x)<\infty.
\]
For \(\lambda\in\{\nu,\eta\}\), set
\[
 \tau_s^\lambda=\lambda(|x|>s),\qquad
 V_{p,s}^\lambda(y)=
 \int_{|x|>s}F_y^p(x/s)\lambda(\dd x),
\]
and let the common retained jet and the two proxies be
\begin{align*}
 C_{p,r-1,s}
 &=\sum_{j=1}^{r-1}s^{-j}B_{p,j}^\nu
  =\sum_{j=1}^{r-1}s^{-j}B_{p,j}^\eta,\\
 A_{p,s}^\lambda
 &=1+C_{p,r-1,s}+V_{p,s}^\lambda-\tau_s^\lambda.
\end{align*}
The sum is empty when \(r=1\).  For all sufficiently large \(s\), both
\(A_{p,s}^\lambda\) are positive probability densities relative to
\(\Omega_p\).  Thus
\[
 k_{p,r,s}^\lambda(x)=s^{-d}p(x/s)A_{p,s}^\lambda(x/s)
\]
are probability densities and the finite, nonnegative proxy energy
\[
 \mathcal E_{p,r,s}(\nu,\eta)
 :=D_{\rm KL}(k_{p,r,s}^\nu\|k_{p,r,s}^\eta)
\]
is well defined.  If
\(\Delta_r=\int x^{\otimes r}(\nu-\eta)(\dd x)\), put
\[
 B_{p,\Delta_r}(y)=
 \frac{(-1)^r}{r!p(y)}\langle\Delta_r,D^rp(y)\rangle,
 \qquad
 \mathcal Q_{p,r}(\Delta_r)
 =\frac12\int B_{p,\Delta_r}^2\dd\Omega_p.
\]
Then
\[
 D_{\rm KL}(p_s*\nu\|p_s*\eta)
 =\mathcal Q_{p,r}(\Delta_r)s^{-2r}
  +\mathcal E_{p,r,s}(\nu,\eta)+o(s^{-2r}).
\]
Moreover \(\mathcal Q_{p,r}\) is finite and positive definite on
\(\operatorname{Sym}^r(\RR^d)\), and hence, law by law,
\[
 s^{2r}D_{\rm KL}(p_s*\nu\|p_s*\eta)
 \longrightarrow\mathcal Q_{p,r}(\Delta_r)
 \quad\Longleftrightarrow\quad
 s^{2r}\mathcal E_{p,r,s}(\nu,\eta)\longrightarrow0.
\]
\end{unnumberedtheorem}

\begin{proof}
We give every kernel-dependent step.  Let
\[
 \mathsf B_{p,j}(y,z)=
 \frac{(-1)^j}{j!p(y)}\langle D^jp(y),z^{\otimes j}\rangle,
 \qquad \mathsf B_{p,0}=1.
\]
Condition \textup{(K1)} gives, for \(1\le j\le r\),
\[
 \|\mathsf B_{p,j}(\mathord\cdot,z)\|_\infty
 +\|\mathsf B_{p,j}(\mathord\cdot,z)\|_{L^1(\Omega_p)}
 \le C_{p,r}|z|^j.
\]
It also gives \(D^rp\in L^1\).  Consequently ordinary translation
continuity in \(L^1\), the integral Taylor formula, and \textup{(K2)} imply
that, for \(|z|\le1\),
\begin{align*}
 &\left\|F_\cdot^p(z)-\sum_{j=0}^r
       \mathsf B_{p,j}(\mathord\cdot,z)\right\|_\infty
 +\left\|F_\cdot^p(z)-\sum_{j=0}^r
       \mathsf B_{p,j}(\mathord\cdot,z)\right\|_{L^1(\Omega_p)}\\
 &\hspace{35mm}\le \varepsilon_{p,r}(|z|)|z|^r,
\end{align*}
where \(\varepsilon_{p,r}\) is bounded on \([0,1]\) and tends to zero at
zero.  Indeed, after subtracting the degree-\(r\) Taylor polynomial, the
uniform remainder is bounded by a constant times
\(|z|^r\omega_{p,r}(|z|)\).  After multiplication by \(p(y)\), the
\(L^1(\Omega_p)\) remainder is bounded by a constant times
\[

 \|\partial^\gamma p(\mathord\cdot-h)-\partial^\gamma p\|_1,
\]
which is \(o(|z|^r)\).  This proves the required local Taylor statement
without a derivative of order \(r+1\).

Define the actual quotient
\[
 q_{p,s}^\lambda(y)=\int F_y^p(x/s)\lambda(\dd x).
\]
Splitting at \(|x|=s\), retaining the exterior translate exactly, and using
the moments gives
\[
 q_{p,s}^\lambda
 =A_{p,s}^\lambda+s^{-r}B_{p,r}^\lambda+R_{p,s}^\lambda,

\]

discarded exterior mode satisfies
\[
 s^{-j}\int_{|x|>s}|x|^j\lambda(\dd x)
 \le s^{-r}\int_{|x|>s}|x|^r\lambda(\dd x)=o(s^{-r}),
 \qquad j\le r.
\]
The same tail-moment estimate gives \(\tau_s^\lambda=o(s^{-r})\).

Translation preserves mass.  Hence \(V_{p,s}^\lambda\ge0\),
\(\int V_{p,s}^\lambda\dd\Omega_p=\tau_s^\lambda\), and integration of
the distributional derivatives of the integrable density \(p\) gives
\(\int B_{p,j}^\lambda\dd\Omega_p=0\).  Therefore each proxy has mass one,
and
\[
 \inf_yA_{p,s}^\lambda(y)
 \ge1-\|C_{p,r-1,s}\|_\infty-\tau_s^\lambda\longrightarrow1.
\]
This is both proxy normalization and proxy positivity; no tail comparison is
used.

We next verify entropy finiteness.  When \(\tau_s^\lambda>0\), convexity of
relative entropy and \textup{(K3)} give, for the normalized exterior mixture
quotient \(Q_{p,s}^\lambda=V_{p,s}^\lambda/\tau_s^\lambda\),
\[
 \int Q_{p,s}^\lambda\log Q_{p,s}^\lambda\dd\Omega_p
 \le\frac{C_{p,r}}{\tau_s^\lambda}
 \int_{|x|>s}\{1+|x/s|^r\}\lambda(\dd x)<\infty.
\]
The elementary inequalities
\(\Phi(\tau q)\le\tau q\log(1+q)\) for \(0\le\tau\le1\), and
\[
 (u+v)\log^+(u+v)\le C\{1+v+\Phi(v)\},
 \qquad 0\le u\le3/2,\quad v\ge0,
\]
then show
\(\int A_{p,s}^\lambda\log^+A_{p,s}^\lambda\dd\Omega_p<\infty\).
The case \(\tau_s^\lambda=0\) is immediate.  Since the two proxies have a
common positive lower bound, their relative entropy is finite.

It remains to identify the quadratic term.  Condition \textup{(K1)} at
order one says \(\|\nabla\log p\|_\infty=L<\infty\).  Thus
\[
 F_y^p(z)\ge e^{-L|z|},\qquad
 q_{p,s}^\lambda(y)
 \ge e^{-L\int|x|\lambda(\dd x)/s}\longrightarrow1
\]
uniformly in \(y\).  The backgrounds tend to one in \(L^1(\Omega_p)\), and
their common jet cancels, so
\begin{align*}
 \|A_{p,s}^\lambda-1\|_1
 &\le\sum_{j=1}^{r-1}s^{-j}\|B_{p,j}^\lambda\|_1
      +2\tau_s^\lambda=o(1),\\
 \|A_{p,s}^\nu-A_{p,s}^\eta\|_1
 &\le2(\tau_s^\nu+\tau_s^\eta)=o(s^{-r}).
\end{align*}
All hypotheses of the two-background KL perturbation lemma are now
satisfied with \(\epsilon_s=s^{-r}\).  Its Hessian and cubic-remainder
calculation gives
\[
 D_{\rm KL}(p_s*\nu\|p_s*\eta)
 =\mathcal E_{p,r,s}(\nu,\eta)
  +\frac{s^{-2r}}2\int
       (B_{p,r}^\nu-B_{p,r}^\eta)^2\dd\Omega_p+o(s^{-2r}).
\]
The moment identity makes the difference in the integral exactly
\(B_{p,\Delta_r}\), proving the decomposition.

Finiteness of \(\mathcal Q_{p,r}\) follows from \textup{(K1)}.  If it
vanishes, then
\[
 \sum_{|\gamma|=r}\frac{\Delta m_\gamma}{\gamma!}
 \partial^\gamma p=0
\]
almost everywhere.  Fourier transformation gives
\(P(i\xi)\widehat p(\xi)=0\), where \(P\) is the corresponding homogeneous
polynomial.  Since \(\widehat p(0)=1\), continuity makes \(\widehat p\)
nonzero on a neighborhood of zero.  Thus \(P\) vanishes on an open set and
is identically zero.  Hence \(\Delta_r=0\), proving positive definiteness.
Nonnegativity of the proxy KL energy proves the final equivalence.
\end{proof}

The hypotheses above are arranged by proof function, not by tail class.
Condition \textup{(K1)} defines and bounds the retained modes, makes their
integrals vanish, and supplies the logarithmic-gradient lower bound.
Condition \textup{(K2)} is exactly the uniform little-\(o\) Taylor remainder;
the \(L^1\) counterpart is automatic because \textup{(K1)} puts \(D^rp\) in
\(L^1\).  Condition \textup{(K3)} is used only to make the retained-tail and
proxy entropies finite.  Neither decay, regular variation, a semigroup law,
radial symmetry, nor isotropy is assumed.  Isotropy merely adds orthogonal
invariance of \(\mathcal Q_{p,r}\).

\begin{unnumberedproposition}[Verified kernels and the Gaussian boundary]
For every order \(r\ge1\), the abstract theorem applies to each isotropic
strictly \(\alpha\)-stable density, \(0<\alpha<2\), to the Poisson kernel in
every dimension, and to every multivariate Student kernel
\[
 p_{\beta,d}(y)=c_{\beta,d}(1+|y|^2)^{-\beta/2},\qquad \beta>d.
\]
For the stable density, the specialization is exactly Theorem
\ref{thm:stable-arbitrary-order-law-by-law-decomposition}, with identical
proxies, energy, and quadratic form.  The standard Gaussian density is not
tail-jet admissible: \textup{(K1)} and \textup{(K2)} fail, and the additive
retained common jet need not be positive.  Thus the abstract theorem makes no
Gaussian claim.
\end{unnumberedproposition}

\begin{proof}
\emph{Isotropic stable kernels.}
Proposition~\ref{prop:stable-kernel-input-package} gives, with
\(\beta=d+\alpha\),
\[
 p(y)\asymp(1+|y|)^{-\beta},\qquad
 |\partial^\gamma p(y)|\le C_\gamma
 (1+|y|)^{-\beta-|\gamma|}.
\]
This proves \textup{(K1)}.  For \(|h|\le1\), the mean-value theorem, the
bound at order \(r+1\), and
\(1+|y|\le2(1+|y-th|)\) give
\[
 \frac{|\partial^\gamma p(y-h)-\partial^\gamma p(y)|}{p(y)}
 \le C|h|,\qquad |\gamma|=r,\quad 0\le t\le1,
\]
so \textup{(K2)} holds.  The two-sided density estimate also gives
\[

\]
which is \textup{(K3)} for every \(r\ge1\).  The abstract definitions of
\(F_y^p\), \(B_{p,j}^\lambda\), \(A_{p,s}^\lambda\), and
\(\mathcal Q_{p,r}\) are respectively the definitions used in
Theorem~\ref{thm:stable-arbitrary-order-law-by-law-decomposition}.  Hence
that theorem is precisely this specialization, not a weakened consequence.

\emph{Poisson kernel.}
At unit height the Poisson kernel on \(\RR^d\) is
\[
 P_1^{(d)}(y)=c_d(1+|y|^2)^{-(d+1)/2}.
\]
The derivative calculation in the next paragraph with \(\beta=d+1\)
verifies \textup{(K1)} and \textup{(K2)}, while the displayed entropy bound
there verifies \textup{(K3)}.  Its spatial dilates are exactly
\(P_s^{(d)}(x)=c_ds(s^2+|x|^2)^{-(d+1)/2}\).  This is also the
\(\alpha=1\) stable member, but the rational formula proves membership
directly, without stable-density estimates.

\emph{Multivariate Student kernels.}
Let \(\beta>d\).  Repeated differentiation shows that every normalized
derivative \(\partial^\gamma p_{\beta,d}/p_{\beta,d}\) is a finite sum of
terms
\[
 c_{\gamma,k}\,
 \frac{y^{\delta_{\gamma,k}}}{(1+|y|^2)^{k}},
 \qquad |\delta_{\gamma,k}|\le2k,
\]
and is therefore bounded.  The same statement one order higher, together
with
\[
 \frac{p_{\beta,d}(y-th)}{p_{\beta,d}(y)}\le C_{\beta,d},
 \qquad |h|\le1,\quad 0\le t\le1,
\]
and the mean-value theorem gives \(\omega_{p,r}(t)\le Ct\).  Finally,
\[
 \sqrt{1+|w+z|^2}
 \le\sqrt{1+|w|^2}+|z|
 \le(1+|z|)\sqrt{1+|w|^2},
\]
so
\[
 \log\frac{p_{\beta,d}(w)}{p_{\beta,d}(w+z)}
 \le\beta\log(1+|z|).
\]
Integration against \(p_{\beta,d}(w)\dd w\) proves \textup{(K3)}.
This supplies a nonstable polynomial-tail family for every \(\beta>d\);
only the value \(\beta=d+1\) is the Poisson/stable case.

\emph{Gaussian obstruction.}
For the standard Gaussian \(g\),
\[
 \partial^\gamma g/g=(-1)^{|\gamma|}H_\gamma,
 \qquad \nabla\log g(y)=-y,
\]
so the normalized derivatives are unbounded and \textup{(K1)} fails at its
first derivative.  The translate quotient
\[
 F_y^g(z)=\exp\{y\mathbin\cdot z-|z|^2/2\}
\]
has infimum zero for every \(z\ne0\); hence the uniform lower bound for the
actual quotients used by the two-background expansion is unavailable.  The
proxy failure is already explicit in dimension one at \(r=2\).  Take
\(\nu=\delta_m\) and
\(\eta=(\delta_{m-a}+\delta_{m+a})/2\), where \(m\ne0\) and \(a>0\).
They have the same moments below order two.  For \(s>|m|+a\) the retained
tails vanish, while the common first Gaussian mode is \(my\); therefore both
prescribed proxies equal \(1+my/s\), which is negative on a half-line.
Thus proxy positivity, the background lower bound, and the bounded cubic
remainder all fail at the same additive-jet step.  Gaussian translate entropy
itself is not the obstruction when \(r\ge2\), since
\(\mathsf H_g(z)=|z|^2/2\).  Weighted Hermite arguments can and do prove
Gaussian first-unmatched-moment asymptotics under stronger input hypotheses,
as recalled above, but they are not instances of this positive additive
tail-proxy mechanism.
\end{proof}

# Verification Before Completion

## Overview

Claiming work is complete without verification is dishonesty, not efficiency.

**Core principle:** Evidence before claims, always.

**Violating the letter of this rule is violating the spirit of this rule.**

## The Iron Law

```
NO COMPLETION CLAIMS WITHOUT FRESH VERIFICATION EVIDENCE
```

If you haven't run the verification command in this message, you cannot claim it passes.

## The Gate Function

```
BEFORE claiming any status or expressing satisfaction:

1. IDENTIFY: What command proves this claim?
2. RUN: Execute the FULL command (fresh, complete)
3. READ: Full output, check exit code, count failures
4. VERIFY: Does output confirm the claim?
   - If NO: State actual status with evidence
   - If YES: State claim WITH evidence
5. ONLY THEN: Make the claim

Skip any step = lying, not verifying
```

## Common Failures

| Claim | Requires | Not Sufficient |
|-------|----------|----------------|
| Tests pass | Test command output: 0 failures | Previous run, "should pass" |
| Linter clean | Linter output: 0 errors | Partial check, extrapolation |
| Build succeeds | Build command: exit 0 | Linter passing, logs look good |
| Bug fixed | Test original symptom: passes | Code changed, assumed fixed |
| Regression test works | Red-green cycle verified | Test passes once |
| Agent completed | VCS diff shows changes | Agent reports "success" |
| Requirements met | Line-by-line checklist | Tests passing |
