PROBLEM. artifacts/SHA256SUMS does not verify. Checked independently:

  cd artifacts && sha256sum -c SHA256SUMS
    -> 11 OK, 1 FAILED: finite_verification.txt

The cause is that the archived verifier output embeds a wall-clock timing. Running
artifacts/verify_finite_claims.py rewrites artifacts/finite_verification.txt, and the
only difference between runs is a line of the form

    elapsed_seconds = 3.607     ->     elapsed_seconds = 3.626

so the file's SHA256 changes on every run and the manifest can NEVER be stable. A referee
who reruns the script - exactly what we invite them to do - gets a failing checksum, which
destroys the machine-verification credibility the manifest exists to establish.

artifacts/deepening_delta_verification.txt has the same problem; check it too.

Note for context, not something to fix here: this repository has core.autocrlf=true, so
text files are checked out with CRLF on Windows while a referee on Linux or macOS will
have LF. Hashes computed over CRLF bytes will not match LF bytes. If you can make the
manifest robust to that - for instance by hashing only files that are already binary-safe,
