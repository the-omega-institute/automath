3612: \begin{lemma}[Gate-witness criterion]
3613: \label{lem:gate-witness-criterion}
3614: A case record is a historical path-verified witness for the safety interface
3615: when it names the source or artifact snapshot surface, the invariant that failed,
3616: the gate decision recorded for that snapshot, and the safe manuscript lesson.
3617: Under the finite-record interface theorem,
3618: Theorem~\ref{thm:publication-safety-interface}, such a witness can support a
3619: case-study claim about the recorded historical gate surface, but not a stronger
3620: command-run, benchmark, live-daemon, rebuild, dynamic-artifact, or semantic
3621: validation claim, unless the corresponding command, source state, environment,
3622: exit code, and log path are also recorded.
3623: \end{lemma}
3624: 
3625: \begin{proof}
3626: The four named fields are exactly the data required by the definition of a
3627: path-verified historical evidence level: they identify the snapshot surface on
3628: which the case is checked, which gate predicate was evaluated, what decision was
3629: recorded, and which bounded claim may be carried into the manuscript.  A live
3630: benchmark, daemon execution, full-source rebuild, dynamic artifact run, or
3631: semantic validator would add an event time, command, source state, environment,
3632: exit code, log path, and usually a new artifact-output surface.  Those fields are
3633: not read by a historical witness.  Therefore a witness record with only the four
3634: path-verified fields supports the bounded case-study claim and cannot be used as
3635: evidence for a fresh command-run assertion.\end{proof}

3637: \begin{proposition}[Path-complete case witnesses]
3638: \label{prop:path-complete-case-witnesses}
3639: Suppose a case-study row is used as load-bearing evidence for
3640: the finite-record interface theorem, Theorem~\ref{thm:publication-safety-interface}.  If the row is path-complete in
3641: the sense above, then the row supplies exactly the evidence surface required for
3642: a path-verified historical snapshot case claim and no evidence surface for a
3643: fresh daemon, full-source, theorem-content, artifact-suite, benchmark, or
3644: semantic-substrate rerun.  In fact every accepted path-complete case row factors
3645: through one of four finite witness skeletons---promotion, route/submission
3646: blocking, theorem-content non-growth, or artifact-limitation disclosure---and its
3647: admissible manuscript lesson is the unique bounded lesson attached to that
3648: skeleton.  Replacing that lesson by a fresh experiment, dynamic validation, live
3649: benchmark, or semantic artifact claim changes the skeleton by adding a
3650: command-run or artifact-semantic coordinate, so the original row no longer
3651: certifies the stronger claim.  In
3652: particular, a promotion row is sufficient only
3653: for the bounded claim that an intake packet is not daemon-visible publication
3654: work before human promotion; a route-overlap row is sufficient only for the
3655: bounded claim that the overlap and submission-state gates blocked advancement
3656: until one of the recorded next actions occurs; a theorem-content row is
3657: sufficient only for the bounded claim that file churn or compilation did not
3658: show substantive theorem growth; and an artifact-limitation row is sufficient
3659: only for the bounded claim that the artifact limitation must be disclosed or must
3660: block promotion.
3661: \end{proposition}
3662: 
3663: \begin{proof}
3664: Let $r$ be a path-complete case row.  By definition, every load-bearing
3665: component of $r$ has a concrete source or artifact snapshot path, directory
3666: manifest, or explicit historical boundary.  The promotion interface names the
3667: candidate surface, human-promotion evidence, active-paper
3668: markers, gate decision, and the bounded manuscript claim; these fields are
3669: precisely the data needed to distinguish inactive intake from publication work.
3670: The route-overlap interface names the active route, the submitted sibling that
3671: creates the chronology constraint, the reason for overlap, the gate decision,
3672: and the finite set of permitted next actions.  These are precisely the data
3673: needed to check whether advancement is allowed without appealing to generated
3674: prose, and the submission-state evidence prevents a route from racing an already
3675: submitted sibling.  The theorem-content interface names the changed surface,
3676: the theorem inventory or hard-lint surface, the substantive-content delta, the
3677: gate decision, and the allowed manuscript claim; these fields are precisely the
3678: data needed to reject extension claims based only on file churn or successful
3679: compilation.  The artifact-limitation interface names the status file, the
3680: limitation ledger, the observed limitation, the gate decision, and the only
3681: manuscript claim that may be carried forward.  These are precisely the data
3682: needed to prevent a failed or bounded artifact check from being promoted into a
3683: stronger dynamic-validation claim.  Lemma~\ref{lem:gate-witness-criterion} then
3684: applies to each such row:
3685: the named paths give the source surface, the interface fields give the failed
3686: invariant and decision, and the last field gives the safe lesson.  The same
3687: lemma also rules out upgrading the row to a command-run claim unless the extra
3688: command-run fields are recorded.  In particular, the proof does not rerun the
3689: publication daemon, overlap scanner, theorem-content detector, artifact suite,
3690: or GroundCompiler evaluator; it proves only that the historical path surfaces are
3691: sufficient for the bounded lessons displayed in the table.
3692: 
3693: It remains to justify the skeleton and uniqueness assertions.  The operational
3694: interface dispatches each case row by its gate family.  A row whose required gate
3695: is promotion has exactly the promotion skeleton; a row whose required gates are
3696: overlap and submission-state has the route/submission-blocking skeleton; a row
3697: whose required gate is theorem-content has the non-growth skeleton; and a row
3698: whose required gates are status and limitation-ledger has the artifact-limitation
3699: skeleton.  These four skeletons are disjoint because their gate sets differ, and
3700: the row's safe-lesson field is part of the finite record checked by
3701: Lemma~\ref{lem:gate-witness-criterion}.  Hence, once the skeleton is fixed, the
3702: only accepted lesson is the bounded lesson printed in that row.  A fresh
3703: experiment or dynamic validation would require the command-run boundary fields in
3704: Definition~\ref{def:operational-acceptance-interface}; an artifact-semantic claim
3705: would require an additional artifact pass record or semantic evaluator surface.
3706: Those coordinates are not read by the path-complete row and are not present in
3707: the four skeletons.  The stronger reading is therefore rejected by
3708: Theorem~\ref{thm:finite-coordinate-determination-boundary} together with the
3709: finite obstruction skeleton, while the original bounded historical lesson remains
3710: accepted.\end{proof}

3738: \paragraph{Case-evidence protocol.}
3739: The four case-study rows below are not additional mathematical theorems; they
3740: are the path-verified protocol records used to instantiate
3741: Lemma~\ref{lem:gate-witness-criterion}.  A row is complete for this purpose when
3742: it names the source or artifact surface, the invariant that failed, the gate
3743: decision, and the safe manuscript lesson.  For the present package the row
3744: protocol is:
3745: \begin{itemize}
3746: \item \emph{Newmath intake isolation}: the intake-seed path and active-paper
3747: detector show that a candidate remains inactive preparation until human
3748: promotion creates \path{2026_*}, \path{main.tex}, and \path{PIPELINE.md}.
3749: \item \emph{Upper-fibers overlap block}: the route identity, submitted sibling,
3750: overlap ledgers, and program-board state show the recorded
3751: \path{deferred_wait_for_prior_submission} decision and the finite next-action
3752: set of closure, merge, supersession, or waiting for prior-route feedback.
3753: \item \emph{Fake-extension block}: the phase-D hard-lint script and
3754: this paper's artifact inventory show a theorem-content-gate rejection of file
3755: churn or compilation that did not add load-bearing theorem content.
3756: \item \emph{Rule110 limitation gate}: the status file, collision-audit ledger,
3757: exhaustiveness ledger, and paper-data reference show a bounded limitation that
3758: must be disclosed or must block artifact claims; they do not show fresh dynamic
3759: validation.
3760: \end{itemize}
3761: Thus the rows prove path completeness and reviewability only in the operational
3762: sense of Lemma~\ref{lem:gate-witness-criterion}; they do not certify fresh
3763: daemon execution, full-source rebuilds, or Rule110 reruns.

3824: \begin{theorem}[Case-witness skeleton rigidity]
3825: \label{thm:case-witness-skeleton-rigidity}
3826: Let \(r\) be one of the four case-study rows in
3827: Table~\ref{tab:case-witnesses}, and assume the path-completeness and
3828: review-bundle coverage conclusions of
3829: Propositions~\ref{prop:path-complete-case-witnesses} and
3830: \ref{prop:review-bundle-case-snapshot-coverage}.  Then the accepted information
3831: carried by \(r\) is exactly one of the following four skeleton lessons:
3832: \begin{enumerate}
3833: \item a promotion skeleton: an intake packet is not daemon-visible publication
3834: work before human promotion;
3835: \item a route/submission skeleton: an overlap or submission-state gate blocks
3836: advancement until one of the recorded next actions occurs;
3837: \item a theorem-content skeleton: file churn or compilation does not by itself
3838: show substantive theorem growth or accepted discovery; or
3839: \item an artifact-limitation skeleton: a bounded artifact limitation must be
3840: disclosed or must block the corresponding artifact claim.
3841: \end{enumerate}
3842: Moreover this skeleton classification is rigid.  Any stronger reading of the
3843: same case row as a fresh daemon run, full-source rebuild, theorem-content
3844: rerun, artifact-suite rerun, benchmark, semantic artifact validation, or
3845: Rule110/GroundCompiler dynamic-validation result is accepted by the
3846: publication-safety interface if and only if the submitted package adds the
3847: positive extension coordinates required for that stronger reading: a new claim
3848: kind when needed, a submitted evidence surface for the run or semantic property,
3849: assigned pass rows for the enlarged gate set, and the command-run tuple
3850: containing command, source state, environment, exit code, and log path whenever
3851: fresh execution is asserted.  Without those coordinates, the case row remains
3852: accepted only at the path-verified historical-snapshot level and the stronger
3853: reading has an inclusion-minimal finite bad subrecord.
3854: \end{theorem}
3855: 
3856: \begin{proof}
3857: By Proposition~\ref{prop:path-complete-case-witnesses}, a path-complete case row
3858: factors through exactly one of the four displayed finite witness skeletons:
3859: promotion, route/submission blocking, theorem-content non-growth, or
3860: artifact-limitation disclosure.  That proposition also identifies the unique
3861: admissible manuscript lesson attached to the skeleton.  By
3862: Proposition~\ref{prop:review-bundle-case-snapshot-coverage}, the local paths used
3863: by the row have a finite review-bundle surface: thirteen total local-path strings
3864: across the four rows, represented by copied snapshots or directory
3865: file-manifests.  Thus the evidence coordinate for \(r\) is a path-verified
3866: historical snapshot surface, not an executable event.
3867: 
3868: Let \(r^{+}\) be a stronger reading of the same row.  If \(r^{+}\) asserts a
3869: fresh daemon run, full-source rebuild, theorem-content rerun, artifact-suite
3870: rerun, benchmark, or dynamic Rule110/GroundCompiler validation, it raises the
3871: evidence level from path-verified snapshot evidence to command-run evidence and
3872: therefore changes the boundary coordinate \(B\).  Clause~A6 of the finite
3873: certificate schema requires the command, source state, environment, exit code,
3874: and log path.  If \(r^{+}\) asserts a semantic artifact property rather than only
3875: a historical limitation lesson, it also adds an artifact-semantic evidence
3876: surface and the assigned pass record for the enlarged artifact claim kind.  If
3877: \(r^{+}\) asserts new theorem-content discovery, it adds the theorem-content or
3878: discovery component and the pinned discovery/interface pass rows.  These are
3879: precisely the positive extension coordinates listed by
3880: Theorem~\ref{thm:finite-extension-budget-normal-form}.
3881: 
3882: If those coordinates are submitted and pass the gates assigned by \(\Gamma\), the
3883: enlarged tuple satisfies the schema clauses, and
3884: Theorem~\ref{thm:record-acceptance-exactness} accepts the stronger finite-record
3885: reading at the declared level.  Conversely, if the stronger reading is accepted,
3886: the same exactness theorem forces every changed coordinate to be present and to
3887: pass the assigned gate checks.  When a required coordinate is absent, the failed
3888: schema clause supplies the minimal bad subrecord: missing submitted evidence,
3889: missing pass row, missing discovery-interface row, or missing command-run tuple.
3890: Theorem~\ref{thm:finite-certificate-obstruction-skeleton} gives
3891: inclusion-minimality.  Hence the original row is rigid at its skeleton lesson and
3892: path-verified snapshot level, while fresh reproducibility or semantic-validation
3893: claims require a separately paid finite extension budget.\end{proof}
