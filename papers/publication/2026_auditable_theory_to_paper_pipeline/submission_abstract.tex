\begin{abstract}
AI-assisted formalization is often described as a local loop in which a model
proposes formal text and a proof assistant accepts or rejects it.  Publication
workflows need a second interface: one that records which generated objects may
support which public claims.  We present a theory-to-paper pipeline, developed
across the \emph{newmath} and \emph{automath} workspaces, that routes each
increment through six explicit roles: source object, formal interface, finite
evidence row, advisory agent action, deterministic gate, and human promotion
boundary.

The contribution is a replay-kernel interface for finite publication auditing.
For the submitted package, a byte-to-atom compiler, fixed Horn schema,
replayable certificate, replay report, theorem-inventory ledger, and digest
bundle certify exactly two positive coordinates: theorem-inventory closure and
bounded fixed-replay record-gate soundness.  A canonical finite-antichain and
obstruction basis make the boundary checkable: accepted readings have finite
certificates, and unsupported upgrades are represented by explicit minimal bad
subrecords until their own rows are supplied.

This gives agents room to search, repair, and criticize while keeping
publication evidence tied to deterministic gates and human promotion decisions.
Case rows for intake isolation, overlap blocking, fake-extension rejection, and
artifact-limitation disclosure illustrate the method at a historical,
path-complete snapshot level.  A single scope register below records the
nonconsequence boundaries, so the abstract can state the positive contribution
without repeating each excluded stronger reading.
\end{abstract}

\section{Motivation}
Proof assistants are excellent at checking obligations they are given.  They do
not decide whether an AI-generated theorem statement is mathematically new,
whether it duplicates a submitted sibling, whether an artifact row is being
overread, or whether an intake note has become an active manuscript.  These are
routing failures: a local object may be coherent while the global claim status is
wrong.

\emph{Newmath} is our structured-source instance.  It separates mathematical
source, Lean-facing interfaces, and finite substrate witnesses.  Lean markers
record one verification axis, but Lean acceptance is not treated as semantic
closure for every BEDC claim.  \emph{Automath} is the research-publication
instance.  It coordinates theoremization, review, overlap checks, novelty
checks, manuscript assembly, and submission packets.  Both workspaces use the
same rule: a generated increment becomes evidence only after its permitted claim
type has been recorded and gated.

\section{Six-role audit interface}
Each accepted increment is compiled into six coordinates:
\emph{source object}, \emph{formal interface}, \emph{finite evidence row},
\emph{advisory agent action}, \emph{deterministic gate}, and \emph{human
promotion boundary}.  If a coordinate is missing, the increment remains a
proposal.  If all coordinates are present only for a finite record, the public
claim is finite-record only.

The technical supplement's foreground theorem package is the proof-carrying
Stage--A replay-kernel closure, with the canonical finite-audit basis used as
its supporting normal form.  That basis proves that each monotone acceptance
predicate is determined by a unique finite antichain of minimal accepting
records, and that unsupported Stage--A upgrades have a canonical bad-subrecord
basis.  A canonical byte manifest, a byte-to-atom compiler, a fixed Horn schema,
a replayable certificate, and a deterministic replay report produce the finite vector
\[
q_{\mathrm{inv}}=\mathsf{true},\quad
q_{\mathrm{rgs}}=\mathsf{true},\quad
q_{\mathrm{src}}=q_{\mathrm{art}}=q_{\mathrm{ext}}=q_{\mathrm{ven}}=
\mathsf{false}.
\]
Here \(q_{\mathrm{rgs}}\) is bounded fixed-replay record-gate soundness for the
fixed Stage--A schema, manifest, replayable certificate, replay report, and
digest bundle.  Older six-role, conditional RGS, theorem-inventory, and
local-support closure results in the supplement are support normal forms for this
vector.  Case-study rows are historical, path-complete method witnesses unless a
fresh command, environment, source state, exit-code, and log row is supplied for
a live validation claim.

This distinction is the main engineering lesson.  The same pipeline can let
agents propose theorem statements, repair manuscripts, search literature, and
criticize venue fit, while reserving certification for deterministic gates and
human promotion decisions.  In practice this prevents four common failures:
treating intake material as active work, routing a submitted sibling as a fresh
paper, accepting file growth as theorem growth, and reading a bounded artifact
manifest as semantic validation.

\subsection{Scope and nonconsequence register}
\label{sec:compact-scope-register}
This subsection is the compact article's single register for excluded stronger
readings.  Later tables and theorem pointers repeat an exclusion only when a
local hypothesis would otherwise be easy to misquote.

\begin{itemize}
\item The positive public vector is exactly \(q_{\mathrm{inv}}\) and bounded
fixed-replay \(q_{\mathrm{rgs}}\).  Fresh formal-source rebuilds, dynamic
artifact semantics, external archive equality, venue/upload status, and general
implementation soundness require their own accepted finite upgrade rows.
\item A script, digest, inventory, or review-bundle row is evidence only for the
coordinate named by its gate.  It is not promoted by paraphrase into proof
assistant soundness, whole-program soundness, semantic artifact validation, or
external publication evidence.
\item Optional split-route mathematical material remains interface-scoped:
Richardson obstruction uses a verified triple on the preserved source-indexed
real domain; printed \(U47,U111\) names specialize only under \((HW)\);
\(U126\) is not a Richardson input; one-orbit obstruction assumes one free
monogenic orbit and same-level ambient-product readout; and numerical height
formulae using the ordinary maximum are conditional on \((\mathrm{EKMP})\).
\item Support normal forms in the supplement may justify dependency rows,
boundary rows, and case-evidence rows.  They do not create additional public
theorem coordinates beyond the finite replay-kernel vector.
\end{itemize}

\section{Positioning}
Proof-assistant infrastructure such as Lean~\cite{deMouraKADR2015Lean} supplies
trusted checking for obligations that have already been routed to an appropriate
formal interface.  LLM theorem-proving systems, including
LeanDojo~\cite{YangEtAl2023LeanDojo}, draft--sketch--prove
workflows~\cite{JiangEtAl2023DraftSketchProve}, Lean-oriented LLM
provers~\cite{XinEtAl2024DeepSeekProver}, and mathematical language
models~\cite{AzerbayevEtAl2023Llemma}, improve proposal, search, and repair.
Formal-library and proof-engineering work, including AFP
mining~\cite{BlanchetteHMN2015AFP} and Isabelle/AFP infrastructure
accounts~\cite{Wenzel2019IsabelleAFP}, studies how formal corpora are curated
and maintained.  Artifact and reproducibility norms, such as ACM artifact
badging~\cite{ACM2020ArtifactBadging} and systems-repeatability
studies~\cite{CollbergProebsting2016Repeatability}, state what computational
objects and reruns can support.

\section{Conclusion}
The useful abstraction is not ``the model proves the theorem.''  It is
``the system routes each generated object to the strongest claim it is entitled
to support.''  Making that routing explicit gives AI agents room to search and
repair without letting polished local output masquerade as accepted
mathematical or publication evidence.
