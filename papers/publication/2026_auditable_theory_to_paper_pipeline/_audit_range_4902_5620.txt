4929: \begin{auditrecord}[Review-bundle archive-equivalence criterion]
4930: \label{audit:review-bundle-archive-equivalence}
4931: An archival replacement for \path{review_bundle/} is accepted by this manuscript
4932: only if it satisfies all rows of
4933: Table~\ref{tab:review-bundle-archive-equivalence}.  Equivalently, it must have
4934: the same manifest identity, the same bundle-version tuple, the same finite
4935: certificate file list, the same SHA-256 content digests at final packaging time,
4936: and the same relative path semantics as the submitted \path{review_bundle/}.
4937: If no such hash-and-manifest archive is supplied, the only accepted support
4938: surface is the exact \path{review_bundle/} directory uploaded with the
4939: submission.
4940: \medskip
4941: \noindent\emph{Verification.} The manifest identity criterion fixes the root record that all bundle-dependent
4942: claims cite: \path{review_bundle/REVIEW_BUNDLE_MANIFEST.json}.  Allowing only an
4943: additional archive locator field prevents the archive from silently changing the
4944: certificate schema, pass-record ledger, submission-interface map,
4945: primary-claim inventory, verifier scripts, verifier logs, pinned-source
4946: snapshot, case-evidence rows, or submission-artifact declaration.  The bundle
4947: version is finite because the current manifest carries the three displayed
4948: fields \path{bundle_kind}, \path{created}, and
4949: \path{public_interface.public_source_commit}; equality of the tuple rules out
4950: substituting a different support bundle or a different pinned source commit.
4951: 
4952: The finite file-list criterion is obtained by following only the manifest and
4953: the machine-readable interface records already used in the proofs: certificate
4954: schema, current pass records, primary-claim inventory, submission-interface map,
4955: verifier scripts and logs, source snapshot, and the case snapshots named in the
4956: case-evidence rows.  This traversal is finite because each record is a finite
4957: JSON or manuscript table row and because generated interpreter caches are not
4958: certificate surfaces.  The content-hash criterion then gives a byte-level test
4959: for every file on that finite list.  If a file is omitted, added as a replacement
4960: for a named certificate surface, or changed bytewise, either the file-list row or
4961: the SHA-256 row fails.  The path-semantics row prevents a hash-correct file from
4962: being moved under a new relative name that would make manuscript paths point to a
4963: different object.
4964: 
4965: When all five rows pass, every path used by a bundle-dependent theorem,
4966: proposition, table row, verifier record, or manifest row denotes the same bytes
4967: under the same relative name and under the same root manifest identity as in the
4968: submitted \path{review_bundle/}.  Thus the archive is equivalent for exactly the
4969: finite certificate checks made in this paper.  When any row fails, a reviewer has
4970: a finite bad subrecord: the changed manifest identity, changed version tuple,
4971: file-list discrepancy, hash mismatch, or path-retargeting witness.  In that case
4972: the archive is not accepted, and the support surface must be exact inclusion of
4973: \path{review_bundle/} in the completed submission.
4974: \end{auditrecord}

5221: \begin{theorem}[Workspace-to-final-package reconciliation]
5222: \label{thm:workspace-final-package-reconciliation}
5223: Let $D_0$ be the digest manifest
5224: \path{review_bundle/FINAL_DIGESTS_SHA256.md}, and let $H_i$ denote the source
5225: state printed in verifier log $i$.  The source-state claim made in Audit
5226: record~\ref{prop:final-immutable-package-state-certificate} is the finite package
5227: claim consisting of these recorded pairs $(H_i,D_0)$, not a claim that every
5228: later reviewer checkout, editor workspace, or post-packaging working tree has Git
5229: \path{HEAD} equal to a single historical commit.  If a current workspace reports
5230: a different Git \path{HEAD} from one of the historical rows, then the verifier-log and
5231: bundle-backed claims of this supplement remain admissible exactly in the
5232: following two reconciled cases:
5233: \begin{enumerate}
5234: \item the submitted support surface is exact inclusion of \path{review_bundle/}, or
5235: an archive equivalent to it, whose finite certificate files match the SHA-256
5236: rows of $D_0$; or
5237: \item the package is deliberately advanced to the current workspace state by
5238: rerunning the three verifier commands and replacing the displayed source-state
5239: record, the verifier logs, and the digest manifest by new matching
5240: source-state--manifest certificates.
5241: \end{enumerate}
5242: In all other cases a mismatch between a later workspace \path{HEAD} and a
5243: recorded historical row does not certify a new package state and does not
5244: invalidate the historical finite package claim $(H_i,D_0)$; it only shows that
5245: the later workspace is
5246: outside the submitted support surface.
5247: \end{theorem}
5248: 
5249: \begin{proof}
5250: The accepted command-result coordinates are finite.  By
5251: Audit record~\ref{prop:final-immutable-package-state-certificate}, the three log
5252: paths, the recorded source-state fields $H_i$, and the manifest $D_0$ form the
5253: source-state record for the verifier runs.  By
5254: Theorem~\ref{thm:final-support-surface-closure}, those log claims are part of the
5255: accepted support surface only when the exact bundle is submitted or when an
5256: archive supplies the same finite file list, digests, and relative path semantics.
5257: Thus case (1) fixes the bytes of the certificate files directly: the reviewer's
5258: ambient checkout may have any Git \path{HEAD}, but the submitted certificate
5259: surface is still the byte-identified finite package $(H_i,D_0)$.
5260: 
5261: Suppose instead that the authors want the later workspace itself to be the
5262: package state.  Then at least one source-state coordinate has changed, namely
5263: the Git \path{HEAD} coordinate.  The verification rule in the scope contract
5264: requires every command-result claim to record its exact command, source commit,
5265: environment, exit code, and log path.  Therefore a new workspace state cannot be
5266: accepted by merely observing the new \path{HEAD}; the three verifier runs must be
5267: rerun against that state, and their logs and digest manifest must be replaced by
5268: consistent source-state--manifest records.  This is case (2).
5269: 
5270: If neither case holds, the later workspace contributes no finite coordinate to
5271: the submitted certificate.  It is not named in $D_0$, it is not an
5272: archive-equivalent representative under Table~\ref{tab:review-bundle-archive-equivalence},
5273: and it is not accompanied by fresh verifier logs satisfying the command-result
5274: record rule.  The finite-coordinate determination boundary of
5275: Theorem~\ref{thm:finite-coordinate-determination-boundary} then forbids silently
5276: using that workspace either to certify a new package or to refute the old
