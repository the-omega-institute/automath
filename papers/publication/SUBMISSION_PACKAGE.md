# 投稿包清单（所有论文适用）

A4 的外审报告暴露了一个我们自己造成的缺口。审稿人写道：

> 本次实际可得附件只有正文 PDF；所谓独立补充材料、Python 脚本、单元测试和存档输出均未随附件提供。下述对补充材料和机器核验的意见只能根据正文及来稿说明作程序性判断，不能替代对相应文件的正式审查。

**后果**：我们把材料迁进补充文档以压缩正文，又没有在投稿时把补充文档交出去，等于把辛苦建立的机器验证信用全部作废——审稿人只能"程序性判断"，不能给我们任何核验分。

## 每次投稿必须提交的内容

| # | 内容 | 说明 |
|--:|---|---|
| 1 | `main.pdf` | 正文 |
| 2 | `supplement.pdf` | **迁出正文的章节所在文档**。若正文有指向补充材料的指针而未提交此文件，那些指针即为悬空 |
| 3 | `artifacts/*.py` | 全部验证脚本 |
| 4 | `artifacts/test_*.py` | 全部测试 |
| 5 | 验证输出存档 | 脚本运行结果（`*.txt` / `*.csv`），使审稿人无需运行即可看到结论 |
| 6 | `artifacts/literature_check.md` | 文献核查记录，支撑优先权叙述 |
| 7 | `REPRODUCE.md` | 一键复现说明：装什么、跑什么命令、预期输出 |

## 铁律：补充材料里不许放核心证明

A9 的外审把这条代价说透了。审稿人写道：

> 最有可能承载原创性的两项主张——representative-rigid terminal 定理与 prescribed-image
> prestack 构造——其证明位于无法取得的补充材料中。正文自己也标明这两项属补充材料。
> 因此我可以评估其陈述与优先权，但**无法从 main.pdf 认证这些证明**。

以及最关键的一句：**"补充材料不是一篇独立的第二论文，它装着核心证明。"**

**后果**：我们为压缩页数把材料迁进补充文档，迁走的偏偏是撑起原创性的那两个证明。
于是最强的两项贡献在评审环节等于不存在——不是被否定，是根本没被看到。这已经是第二次
（A4 一次，A9 一次）。

**规则**：压缩只能迁走**辅助性**材料——例行验算、冗长的情形枚举、数值表格、次要引理的
证明。**支撑主张原创性的证明必须留在正文**，哪怕正文因此更长。审稿人明确说过，长度不是
决定性问题，把核心证明挪出去才是。宁可交一篇 40 页的自洽正文加一份技术附录，
也不要交 48 页正文加 50 页装着核心证明的补充材料。

判据：若某条证明被删去后，正文中某项**原创性主张**就无法被独立核实，那它就是核心证明，
不得外迁。

## 投前自检

- [ ] **被迁出正文的内容里，有没有任何一项原创性主张的证明？** 有就迁回来
- [ ] 正文中每一处指向补充材料的指针，其目标是否在提交包内？
- [ ] `supplement.pdf` 是否为**清空 `.aux` 后从零重建**的产物？（增量编译会靠陈旧辅助文件报假成功）
- [ ] 正文对补充材料的**硬编码编号**是否与补充材料实际编号一致？`\suppref{Theorem~1.11}` 这类写法编号写错**不触发任何 LaTeX 告警**，须逐条按编号与类型核对
- [ ] 验证脚本能否在干净环境跑通？输出是否已随包提交？
- [ ] `SHA256SUMS` 是否为 **LF 换行**？CRLF 会让 `sha256sum -c` 在 Linux/macOS 上全条报错
      （审稿人正是在那里跑），而在 Windows 上自检却"全部通过"。同时须在 `REPRODUCE.md`
      注明该文件应在**论文根目录**下校验，因为其中路径相对根目录
- [ ] 期刊是否允许补充材料？若不允许，须把被迁出的内容**移回正文**，而不是留下悬空指针
